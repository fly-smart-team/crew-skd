# 조종사 전자 로그북 (웹앱)

ACARS **AOC OOOI STATUS** 화면을 찍으면 OUT/OFF/ON/IN이 자동으로 들어가는 로그북입니다.
iPad Safari에서 열어 **홈 화면에 추가**해 쓰는 웹앱(PWA)이라 설치 파일이나 Mac이 필요 없습니다.

**주소:** https://fly-smart-team.github.io/crew-skd/logbook/
(저장소 Settings → Pages가 켜져 있어야 합니다. 루트 README 참고)

칸 구성은 회사 Flight Log(Date, A/C, HL, FLT NO, Route, IRR, Duty, R/O, R/I, Duty time, T/S, N/T, I/T, T/O, L/D)를 그대로 따릅니다.

## 처음 한 번

1. iPad Safari로 위 주소를 엽니다.
2. 공유 버튼 → **홈 화면에 추가**. 이후에는 홈 화면 아이콘으로 엽니다.
   - 이렇게 해야 비행기 모드에서도 열리고, Safari가 오래 안 쓴 사이트의 데이터를 지우는 규칙(7일)을 피합니다.
3. 한 번 인터넷이 될 때 열어 두면 글자 인식 엔진(약 11MB)이 저장되어 그다음부터는 오프라인에서도 스캔됩니다.
4. **설정 › 이월 누계**에 회사 Flight Summary 숫자(예: 총 8584:14, CAP 1954:12)와 기준일을 넣습니다.
5. **구글 드라이브 연결**을 누르면 내 드라이브에 `pilot-logbook.json`이 생기고 자동으로 동기화됩니다.
   - 설정 › 동기화에 연결된 계정 이메일이 나옵니다. **다른 계정으로 바꾸기**를 누르면 계정 고르는 창이 뜨고,
     이 기기 기록이 새 계정 드라이브의 파일과 합쳐져 올라갑니다 (이전 계정의 파일은 지우지 않음). **연결 끊기**는 자동 동기화만 멈춥니다.
   - Google Cloud의 OAuth 동의 화면이 "테스트" 상태이면, 새로 쓸 계정을 **테스트 사용자**에 먼저 추가해야 로그인됩니다.
   (Google Cloud에서 Drive API를 켜야 합니다 → [docs/google-setup.md](../docs/google-setup.md))

## 비행 후

1. MCDU에서 AOC › OOOI STATUS 화면을 띄웁니다.
2. **OOOI 화면 찍기** → 카메라로 찍거나 사진 보관함에서 고릅니다.
3. 확인 화면에서 사진과 값을 비교하고, **등록부호(HL)**와 **T/O·L/D(PF/PM/이륙만/착륙만)**를 고른 뒤 저장합니다.
   - 주황색 테두리 칸 = 오독을 검산으로 고친 칸 또는 확인이 필요한 칸

잘 찍는 요령: 화면 정면에서, 반사를 피해서, 오른쪽 끝(OFF·ON 값)까지 들어오게.

## 입력 화면

- 위쪽은 MCDU **AOC OOOI STATUS** 화면 모양: FLIGHT ID · ORIG/DEST · A/C · REG · DATE · OUT/OFF · IN/ON · BLOCK/FLIGHT.
  시각은 UTC 4자리로 넣으면 다음 칸으로 넘어가고(OUT→OFF→ON→IN), 날짜는 OUT부터 자동. **📷 화면 찍어 채우기**로 사진에서 채울 수도 있음.
- **T/O · L/D**: PF / PM / 이륙만 / 착륙만 / **CRZ (순항 교대)** / **Observer**
  - CRZ → 역할이 순항 교대 조종사로 바뀌고, ICAO 양식은 Co-pilot, FAA 양식은 SIC 칸에 들어감
  - Observer → 기록만 남고 비행시간·누계·출력에는 들어가지 않음
- **FLIGHT ID**는 항공사 코드(기본 KE), **REG**는 HL로 시작 — 숫자만 넣어도 KE731·HL8399로 저장 (설정 › 기본값에서 앞자리 변경)
- **Duty** 칸에서 이 비행의 역할을 고르고, 목록에는 Duty(PIC·F/O·CRZ 등)가 T/O·L/D와 함께 표시
- 실계기(I/T)는 기본으로 **비행시간 − 2분** (회사 로그북 방식, 설정에서 변경 가능)
- **계기 접근**: 횟수 0~5 (기본 1), 종류 ILS / RNP / LOC / VOR / RNP AR / VISUAL (기본 ILS). VISUAL은 계기 접근 누계와 FAA 6개월 요건에 세지 않음
- 예정 비행은 편명·구간·기종·등록부호만 미리 들어가 있고, 비행 전이면 **예정으로 저장**, 비행 후 OOOI를 넣고 **저장**

## 목록 보기 · 필터

- 탭: **오늘·예정**(오늘 비행부터 다가오는 예정 비행, 기록 안 한 지난 비행은 위에 접어서) / **기록**(저장을 마친 비행·시뮬레이터) / **전체**("오늘" 구분선 표시)
- **↑ 오름차순 / ↓ 내림차순**: 탭마다 따로 기억 (기본: 오늘·예정은 오름, 기록·전체는 내림)
- **필터**: 기간(이번 달·지난달·최근 90일·올해·직접 지정), 종류(비행·시뮬레이터), 역할(기장·부기장·PICUS·순항 교대·교육·교관·평가관), 기종, 공항, 등록부호, 야간만, 사진 있는 것만.
  필터를 걸면 결과 편수와 시간 합계가 나옵니다.
- **이 필터 저장**: 지금 탭·정렬·필터를 이름 붙여 저장 → 목록 위 버튼으로 다시 불러옴 (다른 기기와 동기화)
- **선택** 버튼 또는 **기록을 길게 누르기**(0.5초): 줄마다 체크박스가 나옵니다 (길게 누른 줄은 바로 체크됨). 여러 기록을 체크하고(**보이는 것 모두**도 가능) **선택한 기록 삭제** → 사진도 같이 지우고 다른 기기에서도 지워집니다.

## 회사 Flight Log 사진으로 가져오기

로그북 탭 **📄 회사 로그 가져오기** → 회사 Flight Log 출력물 사진을 고릅니다 (옆으로 찍어도 됨).

- 표 테두리를 지우고 글자를 읽은 뒤, **Duty time = R/I − R/O**, T/S ≤ Duty time, I/T = T/S − 2분, 앞뒤 구간 이어짐,
  거리로 계산한 예상 비행시간으로 오독을 바로잡습니다 (예: "06:224" → 06:24, "CWU" → CJU).
- **확인 화면**에서 줄마다 값을 고치거나 뺄 수 있고, 확인이 필요한 줄은 노랗게 표시됩니다. 같은 편의 예정 비행은 기록으로 바꿉니다.
- **같은 날짜에 이미 있는 비행**(같은 편명 또는 같은 구간)은 맨 앞 칸에서 **고치기 / 건너뛰기 / 따로 추가**를 고릅니다.
  값이 같으면 건너뛰기, 다르면 고치기가 미리 골라지고 무엇이 다른지(예: Block 2:45→2:40) 보여 줍니다.
  고치기는 시각·시간·T/O·L/D만 회사 로그 값으로 바꾸고, 함께 탄 사람·접근·메모·사진은 그대로 둡니다.
- 사진 아래쪽의 **Recent Checks**와 **T/O & L/D 훈련** 줄도 읽어서 함께 넣습니다 (이미 있는 것은 빼 둠).
- 숫자만 있는 편명에 붙일 앞자리(OZ/KE)를 확인 화면에서 고릅니다.
- **Flight Summary**(총 시간·CAP·야간·계기)에서 이 표의 비행을 뺀 값을 **이월 누계**(표 첫날 전날까지)로 맞출 수 있습니다.
- T/O·L/D 별표는 위치로 구분합니다. 표 오른쪽 끝이 잘리면 놓칠 수 있으니 표 전체가 나오게 찍으세요.

## 월간 스케줄로 미리 넣기

1. 로그북 탭 **📅 스케줄 가져오기** → 스케줄 엑셀을 고릅니다. 두 양식을 자동으로 구분합니다.
   - **MONTHLY SKD** (.xls, crew-skd 캘린더 앱과 같은 파일): STD·STA를 한국 시간으로 봄 (설정에서 UTC로 변경 가능)
   - **Crew Roster Report** (.xlsx, Flight/Activity · From · STD · To · STA · A/C · Acting rank · Duty · PIC code · Crew ID · Name):
     STD·STA를 **각 공항 현지 시각**으로 읽어 UTC로 바꿈. 역할은 **PIC code**(P1 기장, F1 부기장, P2·F2 등은 교대 조종사로 추정해 확인 표시).
     Duty가 FLY가 아닌 일정(대기·편승 등)은 건너뜀. 편명 끝 문자(KE333**Z**)는 떼고 저장. 회사 기종 코드 32A·2QA·2QB·3QR·3QP·31P는 A321로 들어감 (설정 › 기종에 코드를 추가하면 그쪽이 우선).
2. 내 비행이 **예정 비행**으로 들어갑니다: 편명, 구간, STD/STA, 로그북 날짜, 역할, 기장 이름, 함께 탄 승무원.
   - 역할은 스케줄의 **POSN**(C = 기장, F = 부기장)을 따릅니다. POSN을 못 읽으면 직급(CAP, F/O)으로 추정하고 "역할 확인"으로 표시합니다.
   - 내가 부기장이면 POSN이 C인 사람이 **기장 이름(ICAO 8번 칸)**으로 들어갑니다.
   - 기종은 그 날짜의 경력 단계를 따릅니다.
3. 비행 후 **OOOI 화면 찍기**를 하면 편명과 시각으로 맞는 예정 비행을 찾아 **시각만 채웁니다.** 예정 비행을 눌러 그 안에서 찍어도 됩니다.
4. 등록부호(HL)와 PF/PM을 고르고 저장하면 실제 기록이 됩니다.

- **당일 변경**: 예정 비행을 눌러 편명·구간·STD/STA·기종·역할·기장 이름·함께 탄 조종사를 고치고 **예정으로 저장**. 스케줄에 없던 비행은 **+ 직접 입력**에서 STD를 넣고 **예정으로 저장**.
- **취소된 비행**: 스케줄을 다시 가져오면 그 달 새 스케줄에 없는 예정 비행을 보여 주고 지울지 묻습니다 (앱에서 고치거나 추가한 예정 비행은 그대로). 하나씩은 예정 비행을 열어 맨 아래에서 지웁니다.
- **함께 탄 조종사**: 스케줄의 다른 조종사 이름이 기본으로 들어가고, 당일 바뀌면 고칠 수 있습니다.
- **함께 탄 사람 찾기**: 로그북 검색창에 이름을 넣으면 그 사람과 탄 비행만 보이고 "함께 N회, 처음 ~ 마지막 날짜"가 나옵니다. 요약 화면의 **자주 함께 탄 조종사**에서 이름을 눌러도 됩니다.
- 예정 비행은 누계, 90일 요건, 출력에 들어가지 않습니다.
- 같은 달 스케줄을 다시 가져오면 이미 있는 비행은 건너뛰고, 시각이 바뀐 예정 비행만 고칩니다.
- STD·STA는 한국 시간으로 적혀 있다고 봅니다 (설정 › 스케줄 시각 기준에서 UTC로 바꿀 수 있음).
- 스케줄 파일은 이 기기 안에서만 읽고 어디에도 올리지 않습니다. 함께 탄 승무원은 이름과 직급만 저장합니다(사번은 저장 안 함).

## 조종사 정보 · 경력 단계 · 이월 누계

- **설정 › 조종사 정보**: 이름(영문), 자격증명, 소속 — 출력물 머리말에 들어갑니다.
- **설정 › 경력 단계**: 역할이 바뀐 날짜마다 한 줄 (예: 2014-03-01 부기장 A320 → 2020-07-01 기장 A321 → 2023-01-15 교관 기장).
  새 비행을 입력하거나 스캔하면 **그 비행 날짜의 단계**에 맞춰 역할과 기종이 자동으로 정해집니다. 비행마다 바꿀 수도 있습니다.
- 비행별 역할: 기장(PIC) / 부기장(Co-pilot·SIC) / PICUS / 순항 교대 / 교육 받음(Dual) / 옵저버, 그리고 **교관 비행(IP)**·**심사 비행(평가관)** 표시.
- **설정 › 이월 누계**: 중간에 쓰기 시작하는 분을 위해 총 시간, 기장, 부기장, PICUS, 교관, 평가관, 다인 조종, 야간, IFR, 실계기, 야외, 시뮬레이터, 주·야간 착륙, 계기 접근을 한 번에 넣습니다.

## 출력 (ICAO · FAA · 회사 양식)

**출력** 탭에서 양식과 기간을 고르고 **인쇄 / PDF로 저장**을 누릅니다 (A4 가로).

| 양식 | 칸 | 표기 |
|---|---|---|
| ICAO / EASA (AMC1 FCL.050) | 1 날짜 · 2 출발 · 3 도착 · 4 항공기 · 5 1인 조종 SE/ME · 6 다인 조종 · 7 총 시간 · 8 기장 이름 · 9 주/야간 착륙 · 10 야간/IFR · 11 PIC/Co-pilot/Dual/Instructor · 12 FSTD · 13 비고 | 시각 UTC, 시:분, 일/월/연 |
| FAA (14 CFR 61.51) | 날짜 · 기종/등록 · 출발/도착 · 비고 · 계기 접근 · 주/야간 착륙 · 종류·등급 · 다발 · 터빈 · 야외 · 야간 · 실계기/모의계기 · FFS/FTD · Dual · PIC · SIC · 교관 · 총 시간 | 10진수 시간 |
| 회사 Flight Log | 첫 페이지: 머리말(Name·Empno·A/C·Duty·Nationality) · Flight Summary · Record Recent 90 days · Recent Checks(1년) · T/O & L/D 훈련, 그다음 회사 로그북 칸 그대로 | 시:분 |

- 페이지마다 **이 페이지 합계 / 이전 페이지까지 / 누계**와 서명란이 들어갑니다. 첫 페이지의 "이전 페이지까지"는 이월 누계 + 출력 시작일 이전 기록입니다.
- PICUS는 ICAO 양식에서 PIC 칸(비고에 PICUS), FAA 양식에서 SIC 칸에 들어갑니다. 교관 시간은 PIC 시간과 함께 Instructor 칸에도 들어갑니다.
- 같은 내용을 CSV로도 받을 수 있습니다.
- 요약 화면 **회사 로그 형식**: Flight Summary(Total · A320 Flight · A320 CAP · CAP · Night · Instrument · 이번 달), 최근 90일 T/O·L/D(Flight / SIM Day / SIM Night / TTL)를 기록에서 계산해 보여 주고,
  **Check 추가 · T/O & L/D 훈련 추가** 폼으로 직접 넣을 수 있습니다 (×로 지움, 다른 기기와 동기화). **회사 형식으로 출력** 버튼은 출력 탭으로 바로 갑니다.
  A320 계열은 A319·A320·A321(neo 포함)을 합친 시간이고, 이월 누계는 회사 로그 사진의 Flight Summary로 맞춥니다.
- 요약 화면에는 ICAO·회사 90일 이착륙, **FAA 야간 90일**(일몰 1시간 후~일출 1시간 전, 완전 정지 착륙), **FAA 계기 6개월**(접근 6회·체공)이 함께 나옵니다.

## 사진 인식은 이렇게 동작합니다

| 단계 | 내용 |
|---|---|
| 흑백 변환 | 검은 바탕의 밝은 글자만 남김 (주변보다 확실히 밝은 점만 → 반사·긁힘 제거) |
| 글자 인식 | Tesseract.js (기기 안에서, 인터넷 불필요) |
| 칸 찾기 | `OUT`, `OFF`, `BLOCK` 같은 라벨 바로 아래의 값을 짝지음. 사진이 기울어도 됨 |
| 오독 보정 | MCDU의 빗금 0(Ø)을 8·9·2로, Z를 2·7로 읽거나 맨앞 0을 빠뜨리는 실수를 후보로 만들어 두고, **BLOCK = IN−OUT, FLIGHT = ON−OFF, 지상 이동 시간**이 모두 맞는 조합 중 수정이 가장 적은 것을 고름. 똑같이 그럴듯한 조합이 둘 이상이면 고치지 않고 표시 |
| 다시 읽기 | 처음 읽은 결과가 불확실하면 기울기를 바로잡고 다른 크기로 한두 번 더 읽어서 합침 |
| 날짜 | 화면 DATE는 사진 찍은 시점의 날짜라서, IN부터 거꾸로 날짜를 붙임 (자정 넘김). 로그북 날짜는 회사처럼 한국 날짜 |

실제 MCDU 사진으로 확인한 결과: 한 장에서 4칸(OUT “123192”, ON “9453”, IN “5042”, FLIGHT “8512”)을 잘못 읽었지만 검산으로 전부 복원했고,
같은 사진을 ±4° 기울이기, 원근 왜곡, 흐리게, 35% 크기로 줄이기, 어둡게, 가로로 돌리기 한 변형에서도 시각 6칸이 모두 맞았습니다.

## iCloud Drive 파일로 맞추기 (무료)

회사 iPad처럼 구글을 쓰지 않는 기기용입니다. 설정 › 동기화 · 백업 › **iCloud Drive 파일**.

1. **① iCloud Drive에서 불러와 합치기** → 파일 앱에서 iCloud Drive의 `pilot-logbook.json`을 고름 → 이 기기 기록과 합침
2. **② iCloud Drive에 저장** → 공유 → **파일에 저장** → 같은 위치를 골라 **대치**
- 처음에는 ②만 하면 됩니다. 기록이 바뀌면 위쪽에 "iCloud 파일에 저장 필요 (N건)"이 뜹니다.
- 자동은 아니고, 맞출 때마다 두 번 탭합니다.
- 안드로이드 폰(구글 동기화)과 회사 iPad(iCloud 파일)를 이으려면 가끔 한쪽 파일을 다른 쪽으로 옮겨 ①로 합치면 됩니다
  (예: 폰에서 설정 › JSON 백업 받기 → 나에게 보내기 → iPad에서 ①로 그 파일 선택).
- Apple 개발자 계정(연 $99)이 있으면 **고급: iCloud 자동 동기화**(CloudKit)를 켤 수 있습니다 → [docs/icloud-setup.md](../docs/icloud-setup.md)

## 저장 구조

```
 이 iPad (IndexedDB) — 모든 기능이 오프라인에서 동작
   ├─ 인터넷 연결 시 ─▶ 구글 드라이브 pilot-logbook.json (자동 동기화, 여러 기기 합치기, 삭제도 전달)
   ├─ 설정 › iCloud·파일 앱에 백업 ─▶ 공유 시트 → "파일에 저장" → iCloud Drive
   └─ 설정 › CSV ─▶ 회사 Flight Log 칸 순서 (엑셀·구글 시트)
```

- 스캔 사진은 이 기기에만 저장합니다 (드라이브에는 기록만 올라감).
- 구글 로그인은 1시간 동안 유지됩니다. 그 뒤에는 위쪽 **다시 연결**을 한 번 누르면 됩니다. 그동안의 기록은 기기에 있다가 연결되면 올라갑니다.

## 파일

| 파일 | 내용 |
|---|---|
| `logbook-companylog.js` | 회사 Flight Log 출력물(사진) 해석·검산·이월 누계 계산 |
| `logbook-skd.js` | 월간 스케줄(SKD) → 예정 비행, 스캔과 예정 비행 연결 (`../skd-core.js` 사용) |
| `logbook-core.js` | 화면 해석·검산·날짜·야간·90일·누계·백업·CSV (브라우저/Node 공용, `tests/logbook.test.js`) |
| `ocr.js` | 사진 흑백 변환, Tesseract 실행, 여러 번 읽기 |
| `app.js`, `index.html` | 화면 |
| `store.js` | 기기 저장소 (IndexedDB) |
| `drive.js` | 구글 드라이브 동기화 |
| `sw.js`, `manifest.webmanifest` | 오프라인 실행, 홈 화면 앱 |
| `vendor/xlsx/` | 엑셀 읽기 (SheetJS, Apache-2.0) — 스케줄 가져오기를 오프라인에서도 쓰도록 함께 둠 |
| `vendor/tesseract/` | 글자 인식 엔진과 영어 데이터 (Apache-2.0). CDN 없이도 동작하도록 함께 둠 |

앱 파일을 고친 뒤 배포할 때는 `sw.js`의 `VERSION`과 `app.js`의 `LOGBOOK_VERSION`을 같이 올려야 iPad에 새 버전이 들어갑니다.
